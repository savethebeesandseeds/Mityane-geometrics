# Unit-relation development screen

The [prospective card](../../cards/unit_relation_screen_v1.md) tests **RPB-v18**:
the unchanged v17 learned20 shape block and frozen432 relation weights, with
each generic four-spacing relation vector normalized inside the encoder.
Native32, waveform decoder/training and shared fixed heads remain unchanged.
The model and focused CUDA tests have separate files; previous versions persist.

Use the existing managed container:

```powershell
.\container.ps1 -Action exec -Command @('bash', 'code/evaluation/protocols/unit_relation_screen_v1/admit.sh')
```

Admission captures59 source files, the card, six exact retained input files and
the verified SDK proof. It compiles only the new producer/test, links nine
unchanged generic objects, then runs the new CUDA primitive and typed runner
engineering tests sequentially. It prints its exclusive capsule path.

Then run the declared screen once:

```powershell
.\container.ps1 -Action exec -Command @('bash', 'code/evaluation/protocols/unit_relation_screen_v1/run_screen.sh', '/opt/cuwacunu_embedding/build/rpb-unit-relation-screen/embedding_unit_relation_screen', '/embedding/output/runs/rpb-unit-relation-screen/ADMISSION/freeze', 'v18', '80787,84090', '/embedding/output/runs/rpb-unit-relation-screen/ADMISSION/quality-screen')
```

This is targeted known-cohort development, including the weak v17 Linear case.
The producer only consumes the retained fresh-confirmation legal data; it calls
no generator and no older model. Point0/512, scalers, checkpoints, optimizer/RNG,
full loss traces, three native views, fixed fits and original queries persist.
The pinned standard-library checker replays saved CPU arithmetic only.

`publish_screen.py` derives both the standard tables and every prospective gate
condition from passed checks and the exact matched v17 summary. An intermediate
publication can go into an exclusive ignored directory to decide continuation.
Only a passed gate allows new freezes/runs for81888/82989/85191 with the same
compiled source/card. Retain both source manifests and all quality outputs.

After finishing, `capture_metadata.py` preserves the metadata tools and capsule
inventory; final publication records those hashes. `record_screen.py` adds the
new design while asserting every historical object is unchanged. No baseline
tensor/head/model work is required for matched score reuse.
