# Early/late confirmation saved-arithmetic source tools

The actual completed uJ1Ack audit used the separately reviewed
[cached-object source adjunct](cached_source_adjunct_v4/README.md). Its preserved
v3 attempt stopped before archive decoding because the successful admission
reused three inherited objects. The composite v4 audit passed with explicit
previous compiler evidence and unchanged numerical checks. The linked SOURCE
copies and historical PASS record grant no new release or execution permission.

The three files in `source-manifest.json` are byte-exact copies of the reviewed
FALSE reader, its sole stdlib CPU archive codec, and its declaration-bound
release utility. The stager creates fresh artificial fixture/seal evidence;
historical fixtures, seals, validations and model artifacts are not bundled as
new admission. These files sit outside the compiled confirmation source closure.

Use the project's existing managed Linux container at `/embedding`, documented
launcher, and internal LibTorch environment. Do not run project tools on Windows
or create a substitute container. From a clean checkout:

```bash
cd /embedding
mkdir -p output/runs/rpb-early-mixer-confirmation/audit-tools
python3 -B code/evaluation/tools/early_mixer_confirmation_v1/stage_source_tools.py \
  --stage-directory /embedding/output/runs/rpb-early-mixer-confirmation/audit-tools/independent-early-mixer-confirmation-staged-UNIQUE
```

Use a new `UNIQUE` name. The stager admits the complete tracked source matrix
before hashes, verifies every manifest byte, and creates the codec's fixed
source path only if absent. Identical existing source is reusable; conflicting
or redirected files remain preserved and cause failure. It writes a fresh
FALSE reader, runs that reader's artificial source fixtures, and creates a new
seal, `reader.paths`, and source-stage proof. The derived release changes only
`ORIGINAL` and `PINS`; every function AST remains identical. No model, head,
quality generation, archive payload or measured audit executes during staging.

Publish the new three-path pointer without overwriting an existing one:

```bash
test ! -e output/runs/rpb-early-mixer-confirmation/reader-approved.paths
cp --no-clobber \
  output/runs/rpb-early-mixer-confirmation/audit-tools/independent-early-mixer-confirmation-staged-UNIQUE/reader.paths \
  output/runs/rpb-early-mixer-confirmation/reader-approved.paths
```

This source stage is separate from actual CUDA admission. The documented
`check-early-mixer-confirmation.sh` and `evaluate-early-mixer-confirmation` Make
target capture the new FALSE triple, frozen card, source, binary and actual
engineering test log before generating their fixed fresh cohorts. Keep the
external confirmation cohort namespace distinct from the unchanged reliability
implementation contract recorded in the old four checkpoint companions. The
fifth `.confirmation.pt` and separate snapshot audit bind those two identities.

For a future clean or incremental confirmation admission, use the reviewed
outside-closure wrapper so the checker's own captured log includes all five

```bash

```

The wrapper was syntax-checked and tested with an artificial executable spy,

After a completed new capsule and exact inventory are explicitly authorized,
create a new two-flags-only reader release:

```bash
python3 -B output/runs/rpb-early-mixer-confirmation/audit-tools/independent-early-mixer-confirmation-staged-UNIQUE/release_staged_reader.py \
  --authorized-completed-capsule /embedding/output/runs/rpb-early-mixer-confirmation/early-mixer-confirmation-NEW \
  --inventory-sha256 EXACT_COMPLETED_INVENTORY_SHA \
  --released-directory /embedding/output/runs/rpb-early-mixer-confirmation/audit-tools/independent-early-mixer-confirmation-released-NEW
```

The release reads only completion/inventory/source metadata and never launches
an audit. The original triple stays FALSE and unchanged. Invoke the released
reader once with its explicit completed capsule and exclusive output as its

completed-metadata records and reviewed one-flag tools; they are not stage side
effects. No TEST/stress, best-point selection or promotion follows from staging.

This command copies only absent definitions, reuses identical existing ones,

the exact emission to absent durable destinations. Use each tracked tool's
`--help` for required paths and SHA arguments. Historical quality metadata and
authorization records are not packaged as fresh approval.
