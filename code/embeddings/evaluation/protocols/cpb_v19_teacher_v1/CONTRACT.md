## Evidence lifecycle

The prospective protocol/contract define the question; exact admitted manifests
bind source, environment, data, inherited controls and actual execution. New
engineering receipts establish bounded component behavior. New training/seal/
readout/audit receipts and inherited immutable witness chains establish the
comparison. A later compact record and RESULTS.md report actual counts and
verdict; an independent review states what was inspected or recomputed without
claiming unperformed tensor/model execution. Full generated evidence remains
in ignored named directories; source and compact metadata can be maintained
without publishing datasets, weights, optimizer states or SDKs.

A valid negative comparison can complete the work. An invalid or partial run
cannot be promoted to a scientific negative. None of these documents is itself
evidence of measured improvement or application quality.
