# Configurable content-only ordered relation development screen

This additive protocol trains the separately tagged `RPB-v22.alt-01` candidate
on the exact saved TEMPO-5 observations. The working `RPB-v20.alt-01`, original
capacity experiment and saved-coordinate diagnostic remain unchanged.

The [prospective card](../../cards/configurable_content_relation_v1.md) fixes
the model, initialized controls, data, heads, budget and two-master gate. The
candidate receives visible observations only and learns through the original
waveform reconstruction objective. Its zero-start ordered relation projection
must preserve initialized native32 values exactly, then receive actual CUDA
gradients and weight updates.

The sole architectural change from the separately stopped `RPB-v21.alt-01` is
removing its additive support-fraction coordinates. The new projection sees the
same odd/even content relation coordinates; masks still select valid comparisons
and normalize their covariance. They cannot enter the projection as a separate
density vector. At C3/F9 the relation bank is1944 coordinates and the projection
is20×1944, adding38,880 parameters. The unchanged loss, data, heads and gate
isolate this declared architectural factor; no v21 checkpoint is resumed.

The producer owns one CUDA trajectory per allocated master, typed checkpoints,
native features and original hidden-patch query arrays at0/512. It compares
candidate0 against saved v20 controls without constructing the old encoder.
At both points, every fixed spectral value and validity flag must match those
controls. Typed reload checks every restored parameter and buffer exactly
before the saved-feature extraction. CPU never executes an encoder.

The separate reader fits only trained native32 and learned20 with the unchanged
shared classifiers: six paired fits per master. Initialized complete32 and
learned20 heads are reused after exact export equality. Other saved v20 heads
remain saved controls. Reuse receipts identify the original paths and hashes;
no historical artifacts are copied, renamed or fitted again. The CPU arithmetic
audit replays the candidate heads and saved decisions, including four paired
comparisons per head repetition and validation view.

The independent stdlib publisher checks TRAIN normalization, original source
membership, saved logits, native coordinate associations, frozen checkpoint
metadata, TRAIN scalers, original query targets and prospective gate conditions.
Its original arithmetic helper imports are captured in the new source closure.
This is known-development validation evidence; no TEST, market evaluation or
serving default change follows.

Use the existing managed `cuwacunu_embedding` container and source its runtime
profile. Build products use a separate internal named session:

```sh
source /etc/profile.d/embedding.sh
bash code/embeddings/evaluation/protocols/configurable_content_relation_v1/run_relation.sh admit
# Use the exact new path printed by CONTENT_RELATION_ADMITTED:

```

Admission freezes source/card/settings/input/binary receipts and runs artificial
CUDA and saved-head checks before any candidate quality model. A single capsule
retains `candidates/master-M`, `screen/readouts`, and `screen/published`. Only a
complete audited joint screen pass creates `third-admission.json` and allocates
the third master in a separate `third` leaf. The producer also enforces that
admission before constructing master941103. Failed gates are completed evidence;
failed integrity/runtime stages remain preserved incomplete capsules.

Original manifests are checked before and after quality. Source and binary
hashes are locked across execution. Completion reconciles candidate update/head
counts, reused controls, screen/third provenance and all retained artifact hashes.
Training, native extraction, query capture and CPU-head costs remain separate.
The full completed v21 capsule is also checked before and after; its preserved
measurements are optional descriptive comparisons, with no v21 execution or refit.

The candidate typed checkpoint, native feature and optimizer witness use new
v22 identities. The original compact query/scaler array formats remain shared
with capacity-v1, with their v22 protocol/model/source metadata binding every
new artifact. Shared saved-arithmetic helpers read these arrays without running
any model.

No fresh quality sources, post-encoder PCA, control refits, old encoder execution,
head tuning or adaptive rescue is authorized by this protocol.
