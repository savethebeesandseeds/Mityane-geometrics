# Protocol metadata tools

The maintained metadata layer uses the pinned shared Node runtime through
`bash code/scripts/node.sh`. It freezes source and declared input identities,
captures metadata source and inventories, renders checked saved-score summaries,
and seals new capsules. It does not fit heads, execute an encoder, decode tensors,
or reinterpret an older source identity.

`metadata.mjs` owns the eight screen/confirmation/information source-freeze
adapters, five screen/confirmation summaries, and two metadata capture adapters.
Family-local `.mjs` entry points preserve their CLI names and options. The six
retired publication commands have `.mjs` entry points that preserve the original
failure message and exit status without reading or modifying any registry.

`capsule_cli.mjs` binds the four configurable family capsule APIs to explicit
current repository/build roots and historical capsule path mappings. The source
closure, actual binary `--source-id`, card, configuration and original manifest
pins remain part of each freeze. Capacity tensor binding still uses the retained
independent Python audit; the prospective C++ reader API is deliberately not an
implicit replacement for that certified scientific path.

New JSON uses `mityane-artifact-json-v1`, records `equivalence: not-certified`,
and has a new implementation/source identity. Original Python JSON bytes, hashes,
archived evidence and publication documents remain unchanged. Markdown output is
a compact new rendering of the same retained score populations and conditions;
it does not claim byte equivalence to the old publication. Metadata averages use
exact binary-rational accumulation and ties-to-even conversion, including
cancellation cases, rather than JavaScript's sequential floating sum.

The independent saved tensor codecs, saved CPU mathematics, scientific validators,
numeric configurable publishers, TRAIN diagnostic, their adversarial tests and
the Python relation gate used by those publishers remain in Python. Their source
and arithmetic are research evidence, and retaining their short, explicit
independent numerical implementation avoids changing a scientific reference for
the sake of changing its language. Metadata callers use the Node entry points;
there is no automatic Python fallback for a failed metadata implementation.

The implementation was authored during the Docker recovery and subsequently
validated in the existing managed Linux container after the owner authorized
execution. `metadata_test.mjs`, `cli_integration_test.mjs` and
`preparation_cli_test.mjs` exercise policies, all eight preparation entry points,
both captures, all five summaries, six refusals and synthetic generated-role
binding. Unsupported scores remain unsupported and negative gates remain negative.
These fixtures never decode research payloads or run an encoder. The
[validation record](../../../../../../doc/PYTHON_MIGRATION_VERIFICATION_2026-10-18.md)
distinguishes engineering acceptance from historical numerical/byte equivalence.
