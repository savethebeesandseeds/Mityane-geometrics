# Two-component data-only admission

This implements the coherent two-rhythm proposal as **TEMPO-4** slow-component
timing and separate **AMP-2** component balance, each designed complexity **5/5**.
The [prospective card](../../cards/two_component_information_v1.md) fixes all
signal, nuisance, split, stream, information-rule and acceptance choices.
No encoder accuracy is produced by this protocol.

Use the existing managed development container:

```powershell
.\container.ps1 -Action exec -Command @('bash', 'code/evaluation/protocols/two_component_information_v1/admit.sh')
```

The script allocates an exclusive capsule under
`output/runs/two-component-information-v1`, captures the source/card/SDK closure,
builds only the new data/information programs in a named container session and
runs their engineering fixtures before generating four full task/cohort datasets.
It links unchanged generic shared objects; it never rebuilds or runs an old model.

Masters 910901 and 910902 each supply TRAIN256 and VALIDATION128 rows per task,
with independent source pairs and a pair-shared extra30% deleted validation view.
Each observed-only decision searches at most515 frequency pairs and fits the
selected sinusoidal coefficients using legal cells. It receives no labels,
source IDs, true frequencies or clean waveform. This is an information check,
not a classifier head or encoder feature.

Save12 legal data archives and12 selected-fit witness archives, complete row
populations/reasons, hashes, counts and costs. The standard-library checker
decodes CPU archives and verifies the selected-fit arithmetic, exact deletion
streams and prospective gates. It reruns neither frequency search nor generator.
Data admission can fail while the checker passes: one judges information quality,
the other checks whether the retained evidence is internally correct.

Only after every task/cohort/view information gate passes should a separate
prospective architecture screen allocate fresh quality seeds and run CUDA models.
Preserve any failed recipe or admission; a changed rule/card gets a new identity.
TEMPO-3, existing encoders, classifier recipes and defaults remain intact.
